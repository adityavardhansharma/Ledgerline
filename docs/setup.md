# Setting up Ledgerline

## 1. Clerk

1. Create an application at <https://dashboard.clerk.com> and turn on **Organizations**.
2. Add a custom role `org:accountant` (read and comment) if you want accountant access.
3. Create a **JWT template** named `convex` with these claims:

   ```json
   { "org_id": "{{org.id}}", "org_role": "{{org.role}}", "org_name": "{{org.name}}" }
   ```

4. Copy the template's **issuer** URL; Convex needs it as `CLERK_JWT_ISSUER_DOMAIN`.
5. Put `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` in `apps/web/.env.local`.

## 2. Convex

```bash
cd apps/web
npx convex dev
```

This creates a deployment, writes `NEXT_PUBLIC_CONVEX_URL` to `.env.local`, pushes the functions and keeps
them in sync. Then set the server-side variables:

```bash
npx convex env set CLERK_JWT_ISSUER_DOMAIN https://your-app.clerk.accounts.dev
npx convex env set LL_ENGINE_URL http://localhost:8000
npx convex env set LL_ENGINE_SECRET "$(openssl rand -hex 32)"     # the same value goes in the engine's .env
npx convex env set LL_TOKEN_KEY "$(openssl rand -base64 32)"      # encrypts Xero tokens at rest
npx convex env set SITE_URL http://localhost:3000
npx convex env set XERO_WEBHOOK_KEY your-webhook-key               # from step 3
```

`LL_ENGINE_URL` must be reachable from Convex. With Convex Cloud and the engine on your laptop, expose it with
a tunnel (for example `cloudflared tunnel --url http://localhost:8000`) or run Convex locally with
`npx convex dev --local`.

## 3. Xero

1. Create a **Web app** at <https://developer.xero.com/app/manage>. A Xero business login is all you need;
   ignore its trial organisation and use the Demo Company. Ledgerline requests read-only granular scopes for
   accounts, trial balance, profit and loss, balance sheet, invoices, payments, bank transactions and manual
   journals. New apps don't get `accounting.journals.read`, so syncs use monthly trial balances. When Xero
   grants your app journal access, set `LL_XERO_JOURNALS=true` on the engine; connections switch to full
   journals on their next sign-in to Xero.
2. Redirect URI: `https://<your-deployment>.convex.site/xero/callback` (the Convex HTTP actions URL).
3. Put the client ID and secret in `apps/engine/.env` as `LL_XERO_CLIENT_ID` and `LL_XERO_CLIENT_SECRET`.
4. Optional: under **Webhooks**, subscribe to Invoices and Contacts with the delivery URL
   `https://<your-deployment>.convex.site/xero/webhook`, and copy the webhook key into `XERO_WEBHOOK_KEY`.
5. To test without real books, connect Xero's **Demo Company** when Ledgerline sends you to Xero.

## 4. Finance engine

```bash
cd apps/engine
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env
.venv/bin/uvicorn ledgerline_engine.api:app --reload --port 8000
```

Or `docker compose up engine` from the repository root.

**Hosting the engine on Vercel.** `apps/engine` deploys as its own Vercel project (FastAPI preset, set in
`vercel.json`; `app.py` is the entry point). From `apps/engine`:

```bash
npx vercel link --project ledgerline-engine
npx vercel env add LL_ENGINE_SECRET --environment production --sensitive        # same value as on Convex
npx vercel env add LL_OPENROUTER_API_KEY --environment production --sensitive   # optional: commentary
npx vercel deploy --prod
cd ../web && npx convex env set LL_ENGINE_URL https://<engine>.vercel.app --prod
```

Add `LL_XERO_CLIENT_ID` and `LL_XERO_CLIENT_SECRET` the same way to connect Xero. `LL_OPENROUTER_API_KEY` is optional; without it the
board pack explains that commentary isn't configured.

## 5. Web app

```bash
npm run dev     # from the repository root
```

Open <http://localhost:3000>, create an account and an organisation, then add figures: connect Xero, import
CSV files, or load the sample company.

## Importing CSV files instead of Xero

Xero isn't required. Under **Sync and import**, choose two files:

| File | Columns |
| --- | --- |
| Chart of accounts | `Code`, `Name`, `Type`, optional `System` |
| Journals | `Journal`, `Date`, `Account`, `Description`, `Debit`, `Credit`, optional `Reference`, `Source` and `Contact` (the customer or supplier; it gives the board pack revenue by customer). One signed `Amount` column, debits positive, can replace `Debit` and `Credit` |

`Type` takes Xero's account types (`BANK`, `CURRENT`, `INVENTORY`, `FIXED`, `CURRLIAB`, `TERMLIAB`, `EQUITY`,
`REVENUE`, `DIRECTCOSTS`, `OVERHEADS`, `DEPRECIATN`, `WAGESEXPENSE`, `EXPENSE` and the rest) or plain words such
as "current liability" or "cost of sales". Set `System` to `DEBTORS` and `CREDITORS` on the trade debtor and
creditor accounts; if they're missing, Ledgerline infers them from the account names. Dates may be `YYYY-MM-DD`
or `DD/MM/YYYY`; every journal must balance.

The sample files in `apps/web/public/samples/` show the format. They are generated by
`apps/engine/scripts/sample_company.py`, which checks that the statements tie out before writing them. Importing
needs the finance engine reachable from Convex, as a sync does, because it builds the statements.
